# 一句话说明

这是一套覆盖软件交付全生命周期的 AI 工程工作流，把“先定义、再计划、增量实现、证据验证、审查和发布”编码成 24 个可触发的 Skill。

# 它解决什么问题

AI 编程常见失败不是不会生成代码，而是跳过需求澄清、一次改太多、没有失败测试、把猜测当事实、审查不完整或没有发布回滚。该仓库用阶段化流程和完成门约束这些行为。

# 核心功能

- Define：访谈、想法收敛、规格。
- Plan：依赖排序、垂直切片、验收条件。
- Build：增量实现、TDD、上下文和官方来源驱动。
- Verify/Review：浏览器验证、系统排错、代码质量、安全和性能。
- Ship：Git、CI/CD、弃用迁移、ADR、可观察性和发布。
- 多工具适配、slash commands、专门 reviewer personas 和共享清单。

# 核心技术

核心是结构化 Markdown 指令，不依赖运行时框架。插件清单、命令、hook 和工具目录提供不同 Agent 的安装/触发适配。

# 主要目录

先读 `skills/using-agent-skills/SKILL.md` 的路由图，再按任务只打开匹配的 `skills/<name>/SKILL.md`；检查类材料在 `references/`；工具安装细节在 `docs/`。

# 主要模块

不是软件模块，而是生命周期模块：定义、计划、实现、验证、审查、交付，加上跨阶段的 context、source、security、performance 和 observability。

# 工作方式

任务先被路由到一个或多个 Skill；每个 Skill 提供触发条件、有序步骤、常见借口、危险信号和可检查的完成条件。完整项目可串联多个 Skill，小修复只使用必要子集。

# 适合什么场景

- 为团队建立稳定的 AI 辅助开发基线。
- 防止 Agent 未写 spec 就开始大改。
- 把“测试通过”提升为包含架构、安全和运行时证据的完成标准。
- 统一多种 AI 工具的工程语言。

# 不适合什么场景

- 一行修复却强制跑完整生命周期。
- 把所有 Skill 同时塞进上下文。
- 不理解现有仓库约束就机械执行模板。
- 把插件安装层误认为知识唯一来源。

# 最值得看的东西

`using-agent-skills` 的任务路由、spec 的成功标准和边界、planning 的垂直切片、TDD 的红绿重构、debugging 的可复现闭环、review 的多轴证据，以及 context-engineering 的分层加载。

# 可以暂时不看的东西

各工具的安装说明、市场插件结构、hook 和 persona 包装。除非准备在对应工具中部署，否则先研究普通 Markdown 工作流。

# 对本资料库的价值

它提供了一套适合跨 AI 工具复用的工程主干，可作为以后分析和实施项目时的默认质量框架。

# 30 秒快速判断

需要完整、标准化的软件交付流程时优先查；任务很小或需要深入领域建模/强交互追问时，只选相关 Skill，或结合 Matt Pocock 的专用工作流。
