# 何时应该先查这个项目

当 AI 即将开始一个非平凡功能、需要拆任务、写测试、排错、审查、上线或组织上下文时，先查对应生命周期 Skill。

# 功能：Spec -> Plan -> Build

- 已有方案：规格写清目标、命令、结构、代码风格、测试、边界和成功标准；计划再拆成依赖有序、可验证的小任务。
- 可以复用：成功标准、Always/Ask First/Never 边界、任务验收与验证命令。
- 可以改造：人类审批门根据风险调整，不应每个普通动作都暂停。
- 不建议复制：固定路径、固定文件数量和固定时间阈值作为所有项目的硬规则。
- 成熟度：`A` 级通用思想。

# 功能：TDD 与增量实现

- 已有方案：薄垂直切片，先制造能证明缺失行为的失败，再写最少实现，最后重构和扩大验证。
- 可以复用：测试是行为证据；bug 修复必须有回归保护；每一片都保持可回退。
- 需要适配：探索性原型、UI 视觉工作和遗留系统可能先需要 characterization test 或人工验证。
- 成熟度：`A`。

# 功能：系统化排错

- 已有方案：复现、定位、缩小、修复、保护；失败必须对应用户真实症状。
- 可以复用：先建立反馈循环，保留基线，一次只验证一个假设，修复后用原场景和回归测试双重确认。
- 不建议复制：在证据很少时直接改第一个“看起来可疑”的文件。
- 成熟度：`A`。

# 功能：代码审查与质量门

- 已有方案：正确性、可读性、架构、安全、性能和验证多轴检查；区分必须修复和建议项。
- 可以复用：固定比较范围、先理解意图、对依赖升级单独审查、不要只看测试是否绿色。
- 需要适配：PR 大小和响应时间目标属于团队政策，不是普遍事实。
- 成熟度：`A/B`。

# 功能：Context Engineering

- 已有方案：常驻规则 -> spec/architecture -> 任务相关源码 -> 错误输出 -> 对话历史，逐层按需加载。
- 可以复用：指针代替复制、先读目标文件和相似实现、外部内容作为不可信数据、上下文变长时持久化进度。
- 不建议复制：把核心知识锁进 `CLAUDE.md`、`AGENTS.md` 或某个工具的 rules。
- 成熟度：`A`。

# 不要重复造轮子的部分

- 生命周期路由和阶段边界。
- Spec、任务、Definition of Done 和审查清单的基本结构。
- 红绿重构、回归保护、度量优先和发布回滚原则。
- 按需上下文和显式不确定性处理。

# 仍然值得自己实现的部分

- 领域特定成功指标和风险等级。
- 与现有 CI、issue tracker、部署和安全策略的集成。
- 小任务的轻量路径和审批策略。
- 针对不同 AI 工具能力的薄适配层。

# 决策表

| Capability | Decision | Reason |
| --- | --- | --- |
| 生命周期工程原则 | Reuse | 普通 Markdown 即可表达，工具无关。 |
| 全部 24 Skills 安装 | Reference / Selective reuse | 全装会增加上下文和流程成本。 |
| 插件/命令包装 | Adapt | 每个 AI 工具机制不同。 |
| 共享检查清单 | Reuse with attribution | 通用价值高，但应保留来源。 |
| 团队审批和发布策略 | Build | 必须匹配实际风险和组织权限。 |
